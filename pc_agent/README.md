# LeKiwi PC 에이전트

노트북에 꽂은 SO-101 리더암의 관절 값을 로봇 게이트웨이(웹 오퍼레이터)로 30 Hz로 보낸다.
게이트웨이는 허락된 에이전트의 값만 팔 목표(`lekiwi/arm/goal`)로 낸다.
통신 규약은 [`../docs/agent_protocol.md`](../docs/agent_protocol.md) (v2: v1 + 리더 보정)이다.

- 의존성은 lerobot 하나다. WebSocket 클라이언트는 표준 라이브러리로 직접 짰다.
- ROS2 · rclpy 가 필요 없다. 게이트웨이 패키지도 가져오지 않는다.

## 실행

```bash
cd pc_agent   # 저장소를 받은 폴더 안
conda run --no-capture-output -n lerobot060 python -m lekiwi_pc_agent --robot <로봇 주소> [--port 8080]
```

- `--no-capture-output`을 빼면 conda 가 출력을 끝날 때까지 잡아 두어 아무것도 안 보인다.
- `conda activate lerobot060` 뒤 `python -m lekiwi_pc_agent --robot <로봇 주소>`로 실행해도 된다.
  이렇게 하면 Ctrl+C 때 conda 의 `CondaError: KeyboardInterrupt` 줄이 나오지 않는다.
- `--verbose`: 자세한 로그를 lerobot 것까지 보여 준다.

## 쓰는 순서

1. 노트북에서 위 명령을 켜 둔다. 로봇이 꺼져 있어도 된다. 켜질 때까지 다시 붙는다.
2. 로봇 화면(조작 권한)에서 '이 PC 쓰기'를 눌러 허락한다.
3. 화면에서 포트 · 보정을 고르고 '리더암 연결'을 누른다.
   - 포트 목록은 이 노트북의 `/dev/ttyACM*` 와 `/dev/serial/by-id/*` 이름이다.
   - 보정 목록은 `~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/*.json` 이다.
4. 화면에서 '팔 시작'을 누르면 리더를 따라 팔이 움직인다.

끝낼 때는 Ctrl+C 를 누른다. SIGTERM 도 같다. 리더암 포트를 닫고, 연결을 닫고, 0 으로 끝난다.

- 리더 주기는 5초마다 한 줄씩 나온다.
- 허락 전에도 값은 보낸다. 다만 게이트웨이가 그 값을 팔로 보내지 않는다.
- 게이트웨이와 끊기면 값 보내기를 멈춘다. 리더암은 열어 둔다.
  - 다시 붙으면 리더암 상태를 다시 알리고 값을 이어 보낸다.
  - 60초 안에 다시 붙으면 같은 token 이라 허락이 이어진다.

## 보정 (캘리브레이션 탭)

로봇 화면의 캘리브레이션 탭이 이 에이전트로 노트북 리더암의 보정을 확인하고 만든다 ([`../docs/calibration_plan.md`](../docs/calibration_plan.md)).

- 보정을 쓰는 동안 리더암 값을 보내지 않는다. 스트리밍 중이던 리더암은 먼저 끊는다. '모터와 맞춰 보기'도 끊는다.
- 리더 모터에 토크가 켜져 있으면 새로 보정을 시작하지 않는다.
- 보정 목록에는 이름이 `[A-Za-z0-9_-]{1,40}` 인 파일만 32개까지 나온다.
- 에이전트가 연 리더 포트는 독점(TIOCEXCL)한다. 그동안 다른 프로그램은 그 포트를 열 수 없다.
- 포트는 마지막에 연결한 리더 포트를 쓴다. 없으면 하나뿐인 `/dev/ttyACM*` 를 쓴다.
- **모터와 맞춰 보기**: 보정 파일마다 모터 EEPROM(Homing_Offset · Min/Max_Position_Limit)과 같은지 본다. 읽기만 한다.
- **모터 값으로 파일 만들기**: 지금 모터 값으로 `<이름>.json` 을 만든다. 이미 있는 이름은 거절한다.
- **새로 보정**: lerobot `SO101Leader.calibrate()` 와 같은 순서다. `input()` 대신 화면 버튼을 쓴다.
  1. 시작: 버스를 열고 토크를 끈다.
  2. '제로-포지션 위치 시키기': 팔을 모든 관절 범위의 가운데로 옮긴 뒤 누른다. Homing_Offset 을 쓴다.
  3. 범위 재기: 모든 관절을 끝까지 천천히 움직인다. wrist_roll 은 0~4095 로 둔다. 화면에 관절마다 지금 · 최소 · 최대 tick 이 보인다.
  4. '끝내기': 모터에 쓰고 `<이름>.json` 으로 저장한다. 있던 파일은 `<이름>.json.bak-<날짜시각>` 으로 복사해 둔다.
     저장은 fsync 와 바꿔 끼우기로 하므로, 전원이 나가도 `<이름>.json` 이 비지 않는다.
  - 어느 단계든 '취소'하면 파일을 쓰지 않는다. 제로-포지션 위치 시키기로 쓴 값은 되돌린다. Ctrl+C 로 끝내도 같다.
- 새로 보정하면 같은 자세라도 값이 달라질 수 있다. 예전 데이터셋과 섞어 학습할 때 주의한다.
- 보정 단계 코드는 `lekiwi_pc_agent/calibration.py` 이다. 게이트웨이의 팔로워(르키위 팔) 보정도 같은 모듈을 쓴다.

## 문제 해결

| 메시지 | 뜻 · 할 일 |
|------|------|
| `게이트웨이에 붙지 못했습니다: [Errno 111] Connection refused` | 로봇의 웹 오퍼레이터가 꺼져 있다. 로봇 · 주소 · 포트를 확인한다. 저절로 다시 시도한다 |
| `게이트웨이에 붙지 못했습니다: timed out` · `No route to host` | 주소가 틀렸거나 노트북이 로봇과 같은 네트워크에 없다 |
| `게이트웨이가 업그레이드를 거절했습니다 (HTTP/1.1 404 …)` | 로봇 게이트웨이가 `/agent` 를 모르는 옛 버전이다. 웹 오퍼레이터를 업데이트한다 |
| `게이트웨이가 이 에이전트를 받지 않았습니다: …` | 이미 다른 PC 에이전트가 붙어 있다 (한 번에 하나). 다른 쪽을 끈다 |
| `게이트웨이와 끊겼습니다: …` · `게이트웨이가 3초 동안 답하지 않습니다` | 와이파이가 끊겼거나 로봇 웹 오퍼레이터가 다시 켜졌다. 저절로 다시 붙는다 |
| `허락 전: 로봇 화면에서 "이 PC 쓰기"를 누르세요` | 조작 권한을 가진 화면에서 허락해야 팔이 따라온다 |
| `리더암 오류: 이 PC 에 없는 리더 포트입니다` | 고른 포트가 이 노트북에 없다. USB 를 다시 꽂고 목록에서 다시 고른다 |
| `리더암 오류: 보정 파일이 없습니다` | 그 id 의 보정 파일이 없다. `lerobot-calibrate --teleop.type=so101_leader --teleop.port=/dev/ttyACM0 --teleop.id=<id>` 로 먼저 보정한다 |
| `리더암 오류: 보정 파일 <id>.json 이 모터 값과 다릅니다` | 모터에 든 보정이 파일과 다르다. 아래 '보정이 다를 때'를 본다 |
| `포트 권한이 없습니다` | `sudo usermod -aG dialout $USER` 를 한 뒤 다시 로그인한다 |
| `다른 프로그램이 포트를 쓰고 있습니다` (`Device or resource busy`) | 다른 프로그램(다른 에이전트 · lerobot)이 포트를 독점(TIOCEXCL)하고 있다. 그 프로그램을 끈다. 반대로 에이전트가 리더암 · 보정 버스를 연 동안에는 다른 프로그램이 이 포트를 열지 못한다 |
| `모터가 답하지 않습니다` | 리더암 전원 · 케이블을 확인한다 |
| `리더암 오류: 리더암을 읽지 못했습니다: …` | 쓰는 중에 케이블이 빠졌거나 모터가 답하지 않는다. 값 보내기를 멈추고 포트를 닫는다. 고친 뒤 '리더암 연결'을 다시 누른다 |
| `이 파이썬에 lerobot 이 없습니다` | 다른 환경으로 실행했다. `conda run -n lerobot060` 으로 실행한다 |
| `보정: 팔 토크가 켜져 있습니다 (…). 먼저 팔 힘을 빼세요` | 무언가가 리더암 모터에 힘을 주고 있다. 아무것도 쓰지 않았다. '리더암 연결'을 한 번 했다가 끊으면 lerobot 이 토크를 끈다 |
| `보정: 리더암이 아직 포트를 놓지 않았습니다` | 리더암 연결이 끝나지 않았다. 잠시 뒤 다시 누른다 |
| `리더암 오류: 보정 중에는 리더암을 연결할 수 없습니다` | 캘리브레이션 탭의 보정을 끝내거나 취소한 뒤 연결한다 |
| `보정: 움직이지 않은 관절이 있습니다: …` | 적힌 관절을 끝까지 움직인 뒤 '끝내기'를 다시 누른다. 그때까지 범위 재기가 이어진다 |
| `보정: 이미 있는 보정 이름입니다` | '모터 값으로 파일 만들기'는 덮어쓰지 않는다. 다른 이름을 쓴다 |
| `보정: 보정 이름은 영문 · 숫자 · _ · - 로 40자까지입니다` | 이름을 `[A-Za-z0-9_-]{1,40}` 로 바꾼다 |
| `보정: 어느 리더 포트인지 모릅니다` | 포트가 여러 개다. 리더암을 한 번 연결해 포트를 정한다 |
| `보정: 제로-포지션 위치 시키기 값을 되돌리지 못했습니다` | 취소 · 오류 중에 버스가 끊겼다. 모터에 반쯤 쓴 보정이 남았을 수 있으니 다시 보정한다 |
| `CondaError: KeyboardInterrupt` (Ctrl+C 뒤) | conda 가 찍는 줄이다. 그 위에 `PC 에이전트를 끝냈습니다` 가 있으면 에이전트는 정상으로 끝났다 |

### 보정이 다를 때

에이전트는 보정을 돌리지도 않고, 보정 파일을 모터에 쓰지도 않는다.
lerobot 은 연결할 때 파일과 모터 레지스터(homing offset · 범위)가 같은지 본다.
다르면 아래 둘 가운데 하나다.

- **다른 리더암의 파일이다.** 화면에서 그 리더암의 보정 id 를 고른다.
- **이 리더암의 보정이 바뀌었다.** `lerobot-calibrate` 로 다시 보정한다.
  - lerobot-teleoperate 에서 ENTER 로 파일을 모터에 써도 된다.

### conda run 과 신호

`conda run` 은 Ctrl+C 를 받으면 `CondaError: KeyboardInterrupt` 를 찍고 1 로 끝난다.
터미널의 Ctrl+C 는 에이전트에게도 같이 가므로, 에이전트는 정상으로 정리한다.
`conda run` 프로세스에 보낸 SIGTERM 은 에이전트에게 가지 않는다 (2026-10-22 확인).
그래서 `kill` 로 끌 때는 python 프로세스에 보내거나 `conda activate` 로 실행한다.

## 규약 밖에서 더 하는 일

규약과 맞는 범위에서 다음을 더 한다.

- **WebSocket ping (1초마다).** 게이트웨이의 pong 도 없이 3초가 지나면 끊긴 것으로 보고 다시 붙는다. 와이파이가 조용히 끊기면 TCP 가 오래 알아채지 못하기 때문이다.
- **welcome 뒤 `leader_status` 한 번.** `agent_welcome` 을 받으면 지금 리더 상태를 한 번 보낸다. 다시 붙었을 때 게이트웨이가 리더가 이미 열려 있음을 알게 한다.
- **목록에 있는 것만 연다.** `leader_connect` 의 포트는 지금 목록(`/dev/ttyACM*` · by-id)에 있어야 하고, 보정 id 는 보정 폴더에 있어야 한다. 아니면 `error` 다. 게이트웨이가 다른 시리얼 장치를 열게 할 수 없다.
- **읽기 실패 3번까지 넘긴다.** 3번 연달아 실패해야 `error` 다. 한 번의 응답 누락으로 조작이 끊기지 않게 한다.

## 파일

| 파일 | 하는 일 |
|------|------|
| `lekiwi_pc_agent/__main__.py` | 명령줄 · 신호 · 조립 |
| `lekiwi_pc_agent/agent.py` | 규약: 연결 · 생존 신호 · 포트 · 리더 명령 · 보정 명령 · 다시 붙기 |
| `lekiwi_pc_agent/calibration.py` | lerobot 보정 단계 (리더 · 팔로워 공용, lerobot 말고는 가져오지 않는다) |
