# "이동 설계" 페이지 설계 (대시보드, 브라우저에서 계산)

2026-10-25. 승인: 사용자 ("브라우저에서 계산하는 이동 설계 페이지, 직선 왕복과 원 — 진행해").
이전 안(ROS 노드 `lekiwi_motion`, `lekiwi_ws/src/docs/superpowers/specs/2026-10-25-circle-motion-design.md`)은 보류한다.
측정으로 확인한 사실과 안전 원칙은 그 문서에서 그대로 가져온다.

## 의도

로봇을 라즈베리파이에서 새 ROS 노드를 빌드하지 않고, **대시보드에서 받는 `odom` · IMU 값을 브라우저가 계산해**
직선 왕복과 원을 센서로 확인하며 그리게 한다. 영상 촬영용. 지금까지 같은 속도 명령을 열린 루프로 보내면
로봇마다 다른 원이 나왔다.

## 목표 · 비목표 · 반목표

목표
- 사이드바 "이동 설계" 페이지. 동작 두 가지:
  - **직선 왕복:** 거리(기본 1.0 m) 앞으로 갔다가 같은 거리 뒤로 돌아오는 것이 1회. 1회 또는 무한.
  - **원:** 반지름(기본 0.5 m), 왼쪽/오른쪽, 한 바퀴 또는 무한.
- 속도 입력, 시작 · 정지, 진행 · 오차 표시, 바퀴별 결과(평균 반지름 · 편차 · 복귀 오차), 로그 CSV 저장.
- 로봇 쪽 코드 변경 없음. 파일 복사만으로 배포한다 (빌드 · 재시작 없음).

비목표: 임의 경로, 장애물 회피, 라이다 보정, 팔, 로봇 안에서 도는 제어 (필요하면 같은 로직을 나중에 옮긴다).

반목표 (이러면 돌아가도 실패)
- 센서가 끊기거나 거짓인데 계속 움직인다.
- 창이 가려지거나 연결이 끊겼는데 이전 명령을 계속 쓴다.
- 닫힌 루프인 척하면서 센서가 없을 때 조용히 열린 루프로 간다.
- 직접 조작(키보드)과 이동 설계가 같은 시간에 명령을 보낸다.

## 확인된 사실

lekiwi04 실측 (2026-10-25): `odom` 거리 -1.4 %(2 m 줄자), 자이로 부호 정상(반시계 +), 회전 일치 0.4~3.5 %,
정지 때 자이로 바이어스 ≤ 0.0003 rad/s. 직진 중 자이로 적분이 `odom` yaw 와 어긋남(전진 +0.1 °/s, 후진 -0.15 °/s):
원인 미상이라 방향각에 IMU 를 쓰는 정도는 로봇에서 켜고 끄며 비교한다.

대시보드 계약 (코드 · 실측으로 확인):
- WS `status` 는 약 0.27 s 마다(4 Hz). 페이지의 `channels` 에 `'odom'`, `'imu'` 를 넣어야 담긴다.
- `status.odom` = `{x, y, yaw[rad], vx, vy, wz}`, `status.imu` = `{roll, pitch, yaw[deg], gyro[x,y,z][rad/s], accel[x,y,z]}`.
  IMU 의 `roll`/`pitch`/`yaw` 는 IMU 노드의 자세 추정이고 기울어져 있다(roll -4.8°, pitch -11.5°, 가속도는 수평).
  그래서 방향은 `imu.yaw` 가 아니라 `gyro[2]` 를 적분해 쓴다.
- 조작 명령: WS `{type:'teleop', x, y, yaw, level, pad:'drive'}`. `x`, `y`, `yaw` 는 -1..1 소수 가능(서버가 자른다).
  속도 = `x × levels[level][0]`, `y × levels[level][0]`, `yaw × levels[level][1]` (`status.teleop.pads.drive.levels`).
  서버가 0.1 s 마다 오기를 기대하고, 0.3 s 끊기면 0 으로, 가속 제한(0.4 m/s², 2.4 rad/s²)을 건다. 2 s 끊기면 조작 권한 회수 · 토크 끔.
- 조작 권한은 `ctx.acquire()`, 바퀴 토크는 `POST /api/motor/power {enabled}`, 비상 정지는 상단 바의 전역 버튼.
- 페이지 계약: `export const title`, `channels`, `mount(el, ctx)`, `unmount()`. `ctx.on('update', cb)` 가 status 마다 불린다.
- 로봇이 서빙하는 `web/` 는 `lekiwi_web_operator/web/` 와 바이트 단위로 같다 (Python 은 다름: 로봇은 `lekiwi-gui-ap_mode` 사본).
  이번에는 `web/` 만 건드린다. 04 는 이더넷 `10.42.0.117` 으로도 닿는다.

## 결정

- **제어는 브라우저(자바스크립트)에서.** 순수 로직 모듈(`web/js/motion/*.js`, DOM 없음)과 얇은 페이지(`web/js/pages/motion.js`)로 나눈다.
  순수 모듈은 Node 22 의 `node --test` 로 시험한다 (`tests/js/`, 서버가 내보내지 않는 위치).
- 위치 · 방향 추정: 위치는 `odom` 자세 증분을 융합 방향으로 다시 돌려 쌓는다. 방향은 `gyro[2]` 적분 +
  `odom` yaw 쪽으로 느리게 끄는 보완 필터(시간 상수 기본 100 s, 화면에서 바꿀 수 있다. 근거는 아래 표). "IMU 방향 사용"을 끄면 `odom` yaw 만 쓴다 (기본 켜짐).
- 원 제어: 출발 자세에서 옆으로 r 떨어진 점이 중심. 접선 방향 목표를 반지름 오차만큼 안쪽으로 기울이고(스탠리 방식)
  `wz = dir·v/r + K_HEADING·(방향 오차)`. 직선 왕복: 출발 방향 유지(`wz`) + 가로 오차는 옆걸음(`vy`)으로 잡고,
  끝에 가까워지면 남은 거리에 비례해 속도를 줄인다. 구간 끝에서 1 s 쉰다.
- 기본 속도: 원 0.12 m/s, 직선 0.10 m/s. 입력 속도는 바퀴 상한의 80 % 안으로 막는다 (피드백 보정 여유).
- 안전 (모두 필수):
  - 시작 조건: 조작 권한 있음, 바퀴 토크 켜짐, 비상 정지 아님, 센서 샘플이 1 s 안에 들어옴. 3 s 카운트다운(취소 가능).
  - 센서 샘플이 1 s 넘게 안 오면 정지. 창이 가려지거나 페이지를 떠나면 정지. 권한 · 토크 · 비상 정지 상태가 바뀌면 정지.
  - 폭주: 반지름 오차 > 0.30 m(직선은 가로 오차 > 0.20 m) 또는 방향 오차 > 60° 가 1 s 이상 이어지면 정지.
  - IMU 가 필수다: 2 s 창으로 비교한 회전 속도가 0.15 rad/s 넘게 어긋나면 정지. 같은 창에서 `odom` yaw 가 5° 넘게 변했는데
    자이로가 반대로(또는 안) 돌았으면 정지 (출발 뒤 누적값으로 보지 않는다: 직선 중 느린 방향 보정이 쌓여 거짓 정지한다).
    IMU 가 없으면 시작하지 않는다.
  - 정지할 때는 0 을 1 s 동안 보낸다 (서버도 0.3 s 뒤 0).
  - 카운트다운 동안에도 0 을 0.1 s 마다 보낸다: 서버는 비상 정지 · 조작 끄기 뒤 0 입력을 한 번 받을 때까지 방향 입력을 버린다.
  - 새 센서 샘플이 0.6 s 넘게 안 오면 마지막 명령을 되풀이하지 않고 0 을 보낸다 (1 s 가 되면 정지).
  - 진행 감시: 3 s 동안 명령한 이동 거리의 30 % 도 못 움직이면 정지 (odom 이 값만 새로 오며 얼었거나 바퀴가 막힌 경우).
  - 명령이 단계 상한이나 바퀴 상한을 넘으면 멈추지 않고 세 성분을 같은 비율로 줄인다.
  - 계산 중 예외가 나면 정지. 창이 가려져 있으면 시작하지 않는다.
  - 이 페이지가 열려 있는 동안은 키보드 조작 묶음(`createTeleop`)을 올리지 않는다 (같은 시간에 두 곳이 명령을 보내지 않는다).
- 원 결과는 매 바퀴 `odom` 기준 평균 반지름 · 편차 · 출발점 복귀 오차를 표시하고 CSV 에도 남긴다.
  CSV 열에 `odom` 자세 · `odom` yaw · 자이로 적분 yaw · 융합 yaw 를 모두 넣는다 (어느 방향이 맞는지는 사용자가 바닥 표시로 판단한다).

## 시뮬레이션으로 정한 값 (2026-10-25)

이득: `heading 1.0`, `cross 2.0`, `crossMax 0.5`, `lateral 1.0`, `approach 1.0`, `lookahead 0.6`, `minSpeed 0.02`, `arrive 0.01`, `rampAccel 0.3`
(`web/js/motion/controllers.js` `GAINS`). 센서 지연 0.3 s + 4 Hz 샘플링에서 직선 왕복은 끝점 ± 0.03 m, 가로 ≤ 0.05 m,
원은 반지름 오차 ≤ 0.017 m (모든 설정).

**방향을 어느 센서가 맞게 보는가에 따라 출발점 복귀 오차가 갈린다** (원 4바퀴, 속도 0.12 m/s, 최악 복귀 오차 [m]):

| 설정 | H1 (odom 이 맞고 자이로 바이어스가 거짓) | H2 (자이로가 맞고 odom 이 못 보는 실제 회전) |
|---|---:|---:|
| IMU 방향 끔 (odom 만) | 0.012 | 0.154 |
| τ = 15 s | 0.028 | 0.136 |
| τ = 40 s | 0.053 | 0.105 |
| **τ = 100 s (기본)** | **0.091** | **0.058** |
| τ = 200 s | 0.113 | 0.030 |
| 자이로만 | 0.147 | 0.017 |

반지름 오차는 모든 설정에서 ≤ 0.016 m 이다. 서버는 0 명령에서 램프 없이 바로 서므로(`teleop.py` step) 끝 맞추기는
지연만큼 미리 빼고 마지막 구간에서 속도를 줄인다.

한 숫자로는 두 가설을 다 5 cm 안에 넣을 수 없다 (목표를 말없이 느슨하게 하지 않고 여기에 적는다).
기본 τ=100 은 실측(lekiwi04)에서 자이로-odom 차이의 부호가 이동 방향을 따라 바뀐 것(전진 +, 후진 -)을 H2 쪽 증거로 보고 정했다.
로봇에서 "IMU 방향 사용"을 끄거나 τ 를 바꿔 바닥 표시로 비교해 확정한다. H1 이면 IMU 방향을 끄거나 τ ≤ 40 으로 낮춘다.
시험은 가설별로 맞는 설정을 따로 확인한다 (`tests/js/controllers.test.js`).

1. `node --test "tests/js/*.test.js"` — 추정기, 컨트롤러, 속도 변환, 감시기, 지표 (디렉터리가 아니라 글롭으로 준다: Node 22).

   참 자세 기준으로 반지름 0.5 ± 0.03 m, 로봇 사이 평균 반지름 차이 ≤ 0.03 m, 복귀 오차 ≤ 0.05 m (2~4바퀴째).

4. 실물: 사용자가 옆에서 지켜보며 낮은 속도로 직선 → 원 순서.
